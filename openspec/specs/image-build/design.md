# image-build — Design Rationale

> Imported from `.kiro/specs/github-actions-remote-executor/design.md` (PART 2: Build Design — KIWI build phase; Security Hardening Components; PART 5: Debug Design). Captures the *why* behind `spec.md`; not normative. AMI conversion is in `ami-build`.

## Overview

The attestable AMI is produced in two phases; this capability covers **phase 1**: a GitHub Actions workflow builds a KIWI image inside a Docker container (KIWI_Builder), generates PCR measurements, attests the artifacts with GitHub's attestation service (Sigstore), and publishes them to GHCR with PCR annotations. (Phase 2, AMI conversion, is `ami-build`.) The `Container_Image` used for execution containers is **pulled at server startup**, not baked into the KIWI image — keeping the image minimal and the container version independent of the AMI.

## Build design principles

Reproducible builds (pinned versions, containerized), cryptographic attestation (Sigstore), signature verification before any AMI is built, isolated/ephemeral build environments, infrastructure-as-code, and automated cleanup.

## Key decisions & trade-offs

- **Pin everything, verify integrity.** Third-party Actions are pinned to full 40-char commit SHAs (commented with version/date); the KIWI builder `FROM` to an `@sha256:` digest; the AL2023 repo URL to a specific release; the Build_Instance AMI data source to a specific AMI (not `most_recent`). A CI lint check enforces that no `uses:` references a mutable tag and that `FROM` contains `@sha256:`. Rationale: a reproducible, auditable supply chain — tag rewriting or floating mirrors cannot silently change what ships.
- **Lockfile-enforced, hash-checked Python install.** `uv.lock` is authoritative; the image installs via `uv sync --frozen` or a hash-checked export (`uv export --frozen` → `pip install --require-hashes`), never version ranges from `pyproject.toml`. wolfcrypt ships only sdists, so its tarball is downloaded with hash verification, the wheel is built inside the builder container, and the built wheel's SHA-256 is added to the final `--require-hashes` set — keeping integrity unbroken end-to-end. Script deps (boto3/paramiko in `scripts/pyproject.toml`) are deliberately **not** installed into the image.
- **Rootless Docker, compiled from source on AL2023.** Running Docker rootless under a dedicated `gha-executor` user (UID pinned to 1000) avoids granting host control via a rootful socket. But AL2023's core repo lacks `rootlesskit`, `slirp4netns`, `fuse-overlayfs`, and `libslirp`, so they are compiled from source (pinned commits/tags, GPG/SHA-256 verified) inside the builder and installed into the image overlay; `dockerd-rootless.sh` is fetched from Moby at a pinned, checksum-verified version. **rootlesskit is pinned to v1.1.1** specifically: v2.x emits a third UID/GID mapping entry that triggers `newuidmap` "Invalid argument" errors on kernels rejecting overlapping ranges — and Moby's newer `dockerd-rootless.sh` passes `--detach-netns` which requires rootlesskit v2.1+, so **Moby v20.10.27** is paired with it. `/etc/subuid`/`/etc/subgid` get two non-overlapping 65536-ID ranges; `loginctl enable-linger` keeps the daemon alive without a login session; `ldconfig` + an `ld.so.conf.d` entry make the source-built `libslirp.so` discoverable.
- **Docker daemon hardening.** A rootless `daemon.json` sets `no-new-privileges`, `live-restore: false` (so containers stop with the daemon, no orphans), and an explicit `data-root` on a writable path (the erofs root is read-only). `userns-remap` is omitted because rootless already provides user-namespace isolation. A udev rule gives `gha-executor` 0600 ownership of the TPM device nodes.
- **systemd hardening with deliberate exceptions.** `NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`, `RestrictAddressFamilies`, `StateDirectory`/`LogsDirectory`, `LimitCORE=0` (no core dumps leaking keys/tokens), and `DeviceAllow=/dev/tpm0 rw` (because `ProtectSystem=strict` implies `DevicePolicy=closed`, which would otherwise block the TPM). **`PrivateTmp` is intentionally NOT set**: the service bind-mounts host temp dirs into containers via the Docker daemon, which runs outside a private `/tmp` namespace, so `PrivateTmp=true` would make every bind mount fail — instead `TEMP_STORAGE_PATH` is moved out of `/tmp` to `/var/lib/gha-executor`. `After`/`Requires=user@1000.service` plus an `ExecStartPre` socket-wait handle the rootless-daemon startup race.
- **Host login hardening, unconditional.** `passwd -l root` and masking `serial-getty@ttyS0.service` run regardless of `ENABLE_SSH`, baked into the read-only erofs layer. The serial console stays active for read-only log output (`console=ttyS0`); only the interactive login prompt is removed. SSH debug access, when enabled, is via `ec2-user` and is unaffected.
- **Runtime package minimization.** `appliance.kiwi` keeps a documented allow-list and excludes post-compromise tooling (`awscli`, `binutils`, `python3.11-pip`, `pciutils`); a regression test asserts their absence. `git` stays with documented justification (the Repository Client needs it).
- **Two-phase, fail-closed SSH debug.** SSH must be opted into at *both* build time (include packages, enable `sshd`) and deploy time (open port 22, attach key pair) — a single accidental flag can't expose a production instance. Keys are provisioned via cloud-init/ec2-instance-connect (never baked in). The artifact is annotated `debug=true|false`, and the AMI converter refuses to build from a `debug=true` artifact — or when the annotation is indeterminate — unless `--allow-debug` is explicit, so the gate fails closed.

## Data models (shapes)

The published GHCR artifact bundles the KIWI `.raw` image and `pcr_measurements.json` (PCR4/PCR7), annotated with `pcr4`, `pcr7`, and `debug`, plus the Sigstore attestation bundle. PCR measurements drive downstream attestation verification.
